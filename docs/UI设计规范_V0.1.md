# RentalPF C 端小程序 · UI 设计规范 V0.2

> 依据 `gordondev/uigd.md` + **`ui-ux-pro-max`**（设计智能）+ **`frontend-app-builder`**（前端构建标准）产出。
> 适用于一期 C 端微信小程序（15 屏，汽车 + 设备）。
> 设计系统令牌（Source of Truth）：`design-system/rentalpf/MASTER.md`（工具生成，品牌主色已覆盖为 `#2563EB`）。
> 原型：`prototype/index.html` → `https://gordon310.github.io/RentalPF/prototype/`

## 技能应用记录
- **ui-ux-pro-max**：检索并采纳「移动端触控 44pt/48dp、相邻目标间距 ≥8px、表单必须有 label、提交需 loading→success/error、空状态与骨架屏、焦点态可见、禁止 emoji 当图标」等规则；`--design-system` 生成并持久化设计系统。
- **frontend-app-builder**：以「设计系统 → 忠实实现 → 浏览器核对」流程执行；统一 SVG 图标、容器纪律、状态完整、可访问性；禁用未获批准的多余装饰。
- **未使用 Image Gen**：本环境无图像生成/看图工具，故以「设计令牌 + SVG + 真实界面」方式落地；后续可在有图像能力时补充概念图。

## 0. 理解与假设

| 项 | 内容 |
|---|---|
| 平台 | 微信小程序（一期），原型用手机尺寸 HTML 近似 |
| 界面类型 | 首页 / 取还点 / 列表 / 详情 / 预订 / 订单 / 设置 等 15 屏（哈啰租车式租用流程） |
| 目标用户 | C 端个人租客，主要租高价值设备（投影/相机/镜头等），移动优先 |
| 业务目标 | 提升转化（搜索→详情→下单→支付）、降低操作成本、增强信任（免押/押金透明） |
| 设计系统 | 自研（本规范定义令牌），组件对齐 8pt 网格 |
| 技术栈 | 原生微信小程序 + TDesign/Vant Weapp（原型为 HTML/CSS） |
| 品牌与风格 | 主色科技蓝 `#2563EB`；清晰、稳重、可信；中高保真 |
| 约束 | 移动优先、WCAG AA、金额与押金信息必须显著且可核对 |

**假设**：一期待确认 UI 仅覆盖 C 端；B 端（二期）不在本规范内。**一期品类含「汽车 + 办公设备」两条线**，首页头部提供「租车 / 租设备」切换，共用同一套取还点与租期流程。

## 1. 诊断摘要

新建项目，无既有界面。以「建立一致基线」为目标，评分（基线期望）：

| 维度 | 基线分 | 说明 |
|---|---|---|
| 信息架构 | 5 | 14 屏已定义清晰导航 |
| 布局网格 | 5 | 8pt 网格、卡片化 |
| 视觉层次 | 4 | 价格/押金/状态为主焦点 |
| 色彩 | 5 | 语义色齐全，主色统一 |
| 组件状态 | 4 | 覆盖默认/选中；需补加载/空/错误态 |
| 交互反馈 | 4 | 关键动作有确认；金额扣款需二次确认 |
| 可访问性 | 4 | 对比度达标；点击区 ≥44px |

**最关键 3 点**：① 押金与免押规则必须可视化、可核对；② 归还/定损是纠纷高发点，需证据留存与申诉入口；③ 租期与倒计时需强提示，避免逾期。

## 2. 优化目标

一致性（组件/文案统一）、可用性（3 步内到达核心动作）、信任（费用与押金全程透明）、可落地（令牌化、组件化）。

## 3. 问题与修改建议（基线约束）

| 优先级 | 维度 | 约束 | 具体做法 |
|---|---|---|---|
| P0 | 视觉层次 | 价格/押金易被淹没 | 价格用 `--danger` 强调色 + 加粗；押金单列一行 |
| P0 | 交互反馈 | 扣款/定损不可误触 | 支付、确认定损走二次确认；提交按钮防重复点击 |
| P1 | 组件状态 | 缺加载/空/错误 | 列表页补骨架屏、空状态、失败重试 |
| P1 | 文案 | 押金/免押歧义 | 统一「押金授权（冻结不解冻即不扣款）」「信用免押」措辞 |
| P2 | 可访问性 | 点击区偏小 | 所有可点元素热区 ≥44×44px |
| P2 | 响应式 | 安全区适配 | 用 `env(safe-area-inset-bottom)` 适配全面屏 |

## 4. 布局与组件结构

- 结构：状态栏 → 导航栏（返回/标题/右侧动作）→ 内容区 → 固定操作条 / 底部标签栏。
- 网格：8pt（4/8/12/16/24/32）；卡片间距 12，页面边距 16。
- 组件：`navbar`、`card`、`chips`、`option`(单选)、`checkbox`、`period-tabs`、`steps`、`tabs`、`order-card`、`upload`、`actionbar`、`tabbar`、`feelist`(费用明细)、`banner`(首页广告 slide 轮播)、`booking`(首页取还车头部)、`store`(取还点列表)。
- 核心流程（哈啰租车式）：首页选取还点+时间 → 查设备 → 列表 → 详情 → 预订（保障套餐/押金）→ 实名免押 → 支付 → 订单 → 取还。

## 5. 设计令牌建议

- **颜色**：主 `#2563EB` / 深 `#1D4ED8` / 浅底 `#EFF6FF`；成功 `#16A34A`；警告 `#D97706`；危险 `#DC2626`；正文 `#111827` / 次 `#374151` / 弱 `#6B7280` / 占位 `#9CA3AF`；描边 `#E5E7EB` / `#F3F4F6`；背景 `#F5F7FA`；卡片 `#FFFFFF`。
- **字体**：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei"`；字号 24/20/16/14/12/11；字重 400/500/600/700；行高 1.5–1.6。
- **间距**：4 / 8 / 12 / 16 / 24 / 32（8pt 网格）。
- **圆角**：8（小）/ 12（中，按钮）/ 16（卡片）/ 999（胶囊）。
- **状态色**：成功 `#16A34A`、警告 `#D97706`、危险/价格 `#DC2626`。
- **交互**：`:focus-visible` 2px 主色描边；按压 `scale(.98)`；过渡 150–300ms；`prefers-reduced-motion` 降级。
- **阴影**：`0 1px 2px rgba(0,0,0,.04)`（卡片）、`0 8px 24px rgba(0,0,0,.10)`（浮层/手机壳）。
- **动效**：150–250ms，`cubic-bezier(.2,.8,.2,1)`；按钮按压 `scale(.98)`；列表/详情用骨架屏。

## 6. 交互、状态与文案

- 按钮：默认 / 按压 / 禁用（`--muted-2`）；提交类防重复。
- 单选卡片：选中态主色描边 + 浅底 + 圆点。
- 空状态：列表空时给「去逛逛」引导；网络失败给「重试」。
- 文案统一：`立即租用`、`提交订单`、`押金授权`、`信用免押`、`申请归还`、`确认验收`；金额单位「¥ / 天」。

## 7. 可访问性与响应式

- 对比度：正文与背景满足 WCAG AA（≥4.5:1）；主色白字 ≥4.5:1。
- 触控：热区 ≥44×44px；表单标签与输入关联。
- 响应式：断点 560px；窄屏信息区单列；全面屏安全区适配。
- 多端：原型桌面端居中展示手机壳，移动端全屏。

- [ ] 15 屏均可通过底部标签栏/返回/评审跳转到达
- [ ] 首页头部含完整「取/还门店 + 取/还时间 + 查设备」，与哈啰租车一致
- [ ] 下单前必须先选取还点与租期；取还点由后台配置
- [ ] 预订页含保障套餐（基础/优享/尊享）且计入费用明细
- [ ] 汽车线：列表/详情展示车型、车牌、能源/座位/变速箱；实名页含**驾驶证认证**（设备线可跳过）
- [ ] 汽车线：取还车展示**表显里程 / 油量电量**，押金分**车辆押金 + 违章押金**

- [ ] 主色一致为 `#2563EB`，语义色正确（成功/警告/危险）
- [ ] 费用明细含租金、服务费、押金（免押为 ¥0）、合计，且合计可核对
- [ ] 押金与免押规则在详情/下单两处均可见且措辞一致
- [ ] 归还申请强制拍照/视频，作为定损依据；验收页有申诉入口
- [ ] 订单页含租期倒计时与逾期提示

- [ ] 空/加载/错误状态在列表与订单页有设计
- [ ] 全面屏底部安全区适配，操作条不被遮挡
- [ ] 首页广告 Banner 为 slide 轮播，圆点与滑动同步，可点击跳转，**后台可配置**，未配置时不展示
- [ ] **全程无 emoji 当图标**，图标统一为同一套 SVG（stroke=currentColor、24 视盒）
- [ ] 所有可点元素热区 ≥44×44px，相邻间距 ≥8px
- [ ] 表单均为「label + input」（非 placeholder-only）
- [ ] 主操作按钮有 loading → 成功/失败反馈，防重复提交
- [ ] 列表/订单具备空状态、加载（骨架屏）与失败重试设计
