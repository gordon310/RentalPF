## 1. 目标与范围

**目标**：建立 C 端高价值办公设备租赁小程序的开发需求基线，覆盖选品、计费、押金/免押、下单签约、交付回收、归还定损与结算闭环。业务逻辑对标哈啰租车（取还 → 选品 → 选期 → 计价 → 免押 → 下单支付 → 交付验机 → 使用 → 归还结算）。

**范围内（一期）**：C 端小程序、设备选品与搜索、档期库存、在线计价、信用免押与押金、电子签约、支付、自提/配送、上门回收、归还验收与定损、运营管理后台、消息通知。

**范围外（一期）**：商家入驻、B 端企业账户/合同/审批、对公与月结、多商家分账；B 端能力进入二期。

## 4. 设备品类与商品

- **REQ-CAT-01** 一期品类（聚焦高价值设备）：投影仪、相机、镜头、无人机、直播设备、会议平板/视频会议设备、笔记本电脑、平板等。**一期具体 SKU 清单【待确认】**。
  - **硬性要求**：品类为**后台可配置的多级分类树**（可增删改、可拖拽层级），**程序不得写死任何品类枚举**。运营可自助新建分类（如「相机 → 镜头 → 定焦/变焦」）。
- **REQ-CAT-02** 资产模型（问卷 6）：**贵重设备一机一码（唯一资产 + SN）**，耗材/配件按数量。
- **REQ-CAT-03** 商品属性（问卷 7）：品牌、型号、成色、配置参数、序列号 SN、采购日期、所在仓库/网点、配件清单、实拍图、说明书/电子资料、日/月租金、押金。
- **REQ-CAT-04** 设备状态与档期（问卷 8）：状态机（可租/在租/维修/报废），**必须按档期锁定库存**。
- **REQ-CAT-05** **动态属性 / 规格模板**：每个品类可后台自定义属性字段（文本/数字/单选/多选/图片/布尔），上架商品时按品类模板填写。**程序不得写死字段**。
- **REQ-CAT-06** **上架数据驱动**：商品上架由后台配置完成（品类、属性、租金、押金、档期、图片、配件），无需改代码或发版。
- **REQ-CAT-07** **汽车品类与车辆专属属性**（一期新增）：汽车作为一级品类（经济型 / SUV / 商务 / 新能源等，后台可配置）；车辆专属属性通过属性模板配置，包括**车牌号、车架号 VIN、品牌车型、座位数、变速箱（自动/手动）、能源类型（燃油/纯电/混动）、表显里程、油量/电量、保险险种与到期、年检到期、行驶证**。汽车同样按「一车一码（唯一资产）」管理。

> **设计约束**：商品分两层 —— 「SKU（规格）」+「资产实例（SN）」。下单按档期占用到资产实例，避免超租。
> **反硬编码约束**：品类树、属性模板、计价规则、押金/免押规则、计费周期、赔偿标准等，均为**后台可配置数据**，代码只实现「规则引擎/配置读取」，不内置业务枚举。

## 5. 租期与计费

- **REQ-PRICE-01** 计费周期（问卷 9）：按天 / 周 / 月 / 年 / 合同期。
- **REQ-PRICE-02** 计价模式（问卷 10）：固定单价 / 阶梯价（越久越便宜）/ 套餐（如周租包）/ 一客一议。
- **REQ-PRICE-03** 起租门槛（问卷 11）：**无起租，最短 1 天**。
- **REQ-PRICE-04** 续租 / 退租 / 换机（问卷 12）：支持**续租、换机（维修/升级）**；提前退租规则【待确认】。
- **REQ-PRICE-05** 运费 / 安装费（问卷 13）：**单列收取**。
- **REQ-PRICE-06** **保障套餐（后台可配置）**：基础 / 优享 / 尊享等档位，含保障范围、免赔额、按天或一次性计费；参与费用明细合计。**档位与价格程序不写死**（参照哈啰租车的保险选择）。汽车线与设备线共用，按品类配置不同险种。
- **REQ-PRICE-07 里程规则（汽车）**：可配置日限里程、超里程单价、是否不限里程。
- **REQ-PRICE-08 油量/电量规则（汽车）**：默认**满油/满电取、满油/满电还**，差额按规则补差；记录取还时油量/电量。

### 5.1 汽车线默认规则（对齐哈啰租车，**已采纳**）

| 规则 | 默认值（后台可配置） |
|---|---|
| 计费 | 按天；**超时还车**按小时/天加收超时费 |
| 里程 | 默认**日限 200km**，超里程按 X 元/km；部分车型可设不限里程 |
| 油量 / 电量 | **满油/满电取、满油/满电还**，差额补差 |
| 押金 | **车辆押金**（还车验车后解冻）+ **违章押金**（违章查清后，一般 30 天退还） |
| 保障 | **基础保障默认含**；优享 / 尊享按天可选（车损、三者、免赔额） |
| 取还 | 支持**同店 / 异店**；异店还车费可配置 |
| 租用资格 | 实名 + **驾驶证认证**；**驾龄 / 年龄门槛**可配置（如驾龄 ≥1 年） |
| 违章 | 还车后查询违章；可从违章押金扣除或代缴，留存凭证 |
| 清洁费 | 严重污损可收清洁费（可配置） |
| 禁止事项 | 不得营运/转租/跨省（可配置），违约计入风控与黑名单 |

> 设备线沿用现有规则（免押/押金、按天计费、归还验收、定损），不适用里程/油量/违章规则。

- **REQ-STOCK-04** 多仓/门店调拨（问卷 17）：**需要**。

## 9. 支付、押金与结算

- **REQ-PAY-01** 支付方式（问卷 26）：微信支付、支付宝（对公归二期）。
- **REQ-PAY-02** 押金方式（问卷 27）：**押金授权（预授权/冻结）为主，信用免押兜底**（芝麻信用 / 微信支付分）。押金额度、免押上限与差额补押规则**按设备价格在运营后台逐设备/分类自定义配置，不写死**。高价值相机/镜头一般走押金授权。
- **REQ-PAY-03** 押金退还（问卷 28）：**人工确认后退还**。

- **REQ-PAY-05** 发票（问卷 30）：普票 / 电子发票（C 端个人通常不需要，保留能力）。
- **REQ-PAY-06** 损坏/丢失赔付（问卷 31）：问卷「人工协商」；建议补充**标准赔偿表**用于高价值设备——【待确认】。

## 12. 错误日志与用户反馈（监控）

统一「错误日志中心」，覆盖四类来源：小程序端、后端服务、运营后台、用户主动反馈。

- **REQ-ERR-01** 统一模型 `ErrorLog`：来源 / 级别 / 状态 / 主体 / 环境 / 错误 / 请求 / 关联(trace_id) / 处理 / 指纹。
- **REQ-ERR-02** 来源 `source ∈ {miniapp, server, admin, feedback}`；**每次报错落一条记录**。
- **REQ-ERR-03** 后端自动捕获：中间件生成 `trace_id` 写入响应头；未捕获异常 / 500 自动落库（堆栈 + 请求信息）。
- **REQ-ERR-04** 客户端上报接口 `POST /api/error-logs/`：匿名可报、限流、参数脱敏；小程序全局 `onError` / `onUnhandledRejection` 及接口失败时调用。
- **REQ-ERR-05** 用户反馈接口 `POST /api/feedback/`：带描述与截图 URL；**不做回访**，联系方式非必填。
- **REQ-ERR-06** 后台查看与管理：按来源 / 级别 / 状态 / 时间筛选，按 `fingerprint` 分组，标记处理 / 忽略、备注、导出。
- **REQ-ERR-07** 指纹与分组：`source + error_type + 规范化 message + page`；每次仍单独落库，后台按指纹聚合。
- **REQ-ERR-08** 隐私与保留：手机号 / 令牌 / 密码等脱敏；**默认保留 180 天**；上报接口限流（匿名 20 次/分）；仅运营团队可见。

## 13. 技术与非功能（NFR）

- **REQ-NFR-01** 终端（问卷 43）：一期 **小程序 + H5 + Web 管理后台**；二期 **B 端 APP 或 PWA**。
